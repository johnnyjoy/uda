# Work Order 015 — Common Table Expressions (CTE / WITH)

## Execution Context

Target coding agent: **OpenAI GPT-5.1-codex** operating in an Opencode workflow.

This work order introduces **Common Table Expressions (CTEs)** to UDA.

CTEs must be implemented as **structured query state**, not as raw SQL prefixes.

This work order must preserve:

- immutable builders
- deterministic SQL compilation
- dialect-owned SQL rendering
- Database as the sole execution surface
- the existing builder → dialect → Sql → Database → Driver → PDO pipeline

This work order is about **WITH / WITH RECURSIVE support**, not arbitrary SQL preambles.

# Goal

Allow developers to define named CTEs fluently and use them in queries without escaping the system.

Target usage:

```php
$totals = $db->select(
        'department_id',
        Expr::count('id')->as('employee_count')
    )
    ->from('employees')
    ->groupBy('department_id');

$rows = $db->select(
        'department_id',
        'employee_count'
    )
    ->with('totals', $totals)
    ->from('totals')
    ->where('employee_count')->gt(5)
    ->rows();
````

Expected SQL:

```sql
WITH totals AS (
    SELECT department_id, COUNT(id) AS employee_count
    FROM employees
    GROUP BY department_id
)
SELECT department_id, employee_count
FROM totals
WHERE employee_count > :p1
```

Recursive target usage:

```php
$seed = $db->select('id', 'parent_id')
    ->from('nodes')
    ->where('id', $rootId);

$step = $db->select('n.id', 'n.parent_id')
    ->from('nodes n')
    ->join('tree t', 't.id = n.parent_id');

$tree = $seed->unionAll($step);

$rows = $db->select()
    ->withRecursive('tree', $tree)
    ->from('tree')
    ->rows();
```

# Architectural Intent

CTEs are **query-root structural inputs**.

They are not raw SQL strings prepended to compiled queries.

Conceptually:

```text
query root
  ctes [
    { name, query, recursive? }
  ]
  main statement
```

Compilation order:

```text
builder state
→ dialect compiles CTE block
→ dialect compiles main statement
→ Sql value object
```

Execution remains unchanged:

```text
builder terminator
→ Database
→ Driver
→ PDO
```

# Requirements

## 1. Fluent API

Add root-level CTE methods to applicable builders.

Minimum required public methods:

```php
with(string $name, Select $query)
withRecursive(string $name, Select $query)
```

Optional additive method if cleanly implementable:

```php
withMany(array $ctes)
```

but do not add this unless it stays simple.

Primary target usage:

```php
$db->select()
   ->with('name', $query)
   ->from('name')
   ->rows();
```

Multiple CTEs must be supported via repeated chaining:

```php
$db->select()
   ->with('a', $q1)
   ->with('b', $q2)
   ->from('a')
   ->join('b', '...')
   ->rows();
```

Builders must remain immutable.

---

## 2. Supported Statement Types

CTE support must be added where structurally appropriate.

Minimum required:

* `Select`

Strongly preferred if already cleanly supported by current builder architecture:

* `Insert`
* `Update`
* `Delete`
* `Upsert` where backend strategy allows

If supporting write-statement CTEs would destabilize the design, this work order may limit execution support to `Select` only, but the documentation and tests must say so explicitly.

Do not fake support.

---

## 3. CTE Naming Rules

CTE names must be validated like identifiers/aliases.

Examples:

Valid:

```text
totals
employee_tree
cte1
```

Invalid names must fail early.

No quoted raw name hacks in this work order.

---

## 4. Recursive CTE Support

Support:

```php
withRecursive('name', $query)
```

This must compile to:

```sql
WITH RECURSIVE name AS (...)
```

where the backend supports it.

Dialect must handle backend differences.

If a backend does not support recursive CTEs, fail explicitly.

---

## 5. Parameter Merging

CTE params must merge into the parent query deterministically.

Given:

* CTE A params
* CTE B params
* main query params

the final SQL must produce:

* one deterministic param bag
* stable param ordering
* no collisions

This requirement is absolute.

---

## 6. Table Attribution

Tables referenced inside CTEs must propagate to the final `Sql` object.

Example:

```sql
WITH totals AS (
    SELECT department_id
    FROM employees
)
SELECT *
FROM totals
```

must preserve `employees` in table attribution.

If multiple CTEs exist, all referenced tables must be merged.

Do not attempt to infer tables from raw CTE names alone. Use builder/query state.

---

## 7. Dialect Compilation

Dialect must render CTEs as part of normal statement compilation.

Dialect responsibilities:

* compile `WITH`
* compile `WITH RECURSIVE` where supported
* render multiple CTE entries in stable order
* render each CTE query in parentheses
* compile the main statement after the CTE block

Dialect must not:

* scatter CTE logic across unrelated methods
* force builders to branch on backend names
* degrade to string-prepend hacks

---

## 8. Interaction with UNION / Subqueries / Expr

CTEs must compose correctly with:

* subqueries
* derived tables
* `UNION` / `UNION ALL`
* `Expr`

Examples that must work:

* CTE built from a union query
* main query using `fromSub(...)` and `with(...)`
* grouped CTE using `Expr::count(...)`

No special-case corruption of compilation order.

---

## 9. Deterministic SQL

Given the same builder state, compilation must produce the same:

* SQL string
* parameter names
* parameter order
* table list
* metadata hints

Multiple chained `with(...)` calls must preserve insertion order.

No hidden reordering.

---

## 10. Alias and Reference Discipline

CTE names are structural references, not ordinary tables.

The builder must allow:

```php
->from('totals')
```

after `with('totals', ...)`

but this work order does not require semantic validation that every CTE reference exists before use.

Do not build a query symbol table.

Keep it simple.

# Philosophy

CTEs are one of SQL’s most powerful structural tools.

They improve:

* readability
* decomposition
* reuse
* recursive querying
* analytical query composition

UDA must support them in the same disciplined way it supports subqueries and unions:

* fluent
* deterministic
* dialect-aware
* execution-neutral

CTEs are query structure, not a string prefix hack.
